# 架构

## 一句话

Kiln 把「一个微应用」抽象成一份**声明**加一个**四动词契约**，然后让构建、宿主、各类 agent 分别消费同一份声明。三者互不知道对方存在。

## 五层，依赖单向向下

```
surface   入口面   CLI / MCP stdio · Studio 另提供本机 HTTP
   │
host      宿主面   执行器 · 能力网关 · 策略 · 插件注册表
   │
pact      契约面   四动词 · 加载 · 校验 · 适配器导出
   │
forge     烧制面   校验 → 契约产物（不打包）
   │
grain     原料面   清单 schema · 错误码 · 结构化错误
```

| 层   | 包         | 只做一件事                                             | 明确不做                 |
| ---- | ---------- | ------------------------------------------------------ | ------------------------ |
| 原料 | `#grain`   | 清单的类型与校验、错误码表、`KilnError`                | 不读入口代码、不碰运行时 |
| 烧制 | `#forge`   | 校验通过后产出可交付的契约文件                         | **不打包、不部署**       |
| 契约 | `#pact`    | 加载 cast、对齐声明与实现、把契约翻成各家 agent 的形状 | 不执行副作用、不做授权   |
| 宿主 | `#host`    | 授权判定、能力注入、执行动词、插件装载                 | 不知道 agent 是谁        |
| 入口 | `#surface` | 命令、参数、退出码、输出格式                           | 不含业务逻辑             |

产品层 `packages/one` 与交付层 `one/` 位于五层之上，只向下调用 `grain` / `pact` / `host` / `surface`，不改四动词语义：

```
交付层  one/          AGENT.md · up.json · checksums.json · 默认应用
产品层  packages/one  启动编排 · 授权 · 客户端注册 · 握手自检 · 状态面板
------------------------------------------------（以下是原内核，未改动分层）
surface / host / pact / forge / grain
```

产品层新增的是「让普通用户与 agent 接得上」的能力，不把业务逻辑塞进内核：默认应用仍是一个普通 cast，遵循同一份清单与能力网关。详见 [ONE.md](./ONE.md)。

依赖只能向下。`grain` 不知道 `pact` 存在；`pact` 不知道 `host` 存在。这条规则是硬约束，违反了会立刻在 import 上暴露。

## 独立化新增的三个模块

为让项目可独立分发、并适配任意 agent，在原有五层之外补了三个模块，全部遵守「依赖只能向下」：

- **`platform`（基础面，最底层）**：只做 OS / 架构 / Node / Shell / 家目录 / 路径归一化探测，另含后台进程工具（状态文件、存活探测、优雅停止）。上层不再直接判断 `process.platform`。
- **`agents`（接入面，位于 surface 之上）**：`AgentBridge` 进程内接口 + `mcp | openai | plain` 三种描述投影 + 通用 HTTP 网关（限流 / 并发 / 超时三道闸门）。新增一个 agent 生态只需加一个投影函数，不动内核。
- **`coding-agent`（可选消费者）**：内置的工具调用循环，只依赖 `agents`，默认关闭，删掉不影响任何其他模块。

另有一个不占层的**项目生成器** `fusion/scaffold.ts`：`kiln new` 与 `kiln cast init` 共用同一套模板，产出能直接通过 `check` 的 cast。它属于开发期工具，不参与运行时调用链。

完整的模块划分、agent 接入方式、跨平台策略、交付范围与验收标准见 [STANDALONE.md](./STANDALONE.md)。

## 为什么这样切

上游两个项目的切法都不长这样：一个按「组件 / 工具链 / 云适配器」切，一个按「入口 / 装配 / 适配器 / 服务 / 执行 / 契约」切六层。它们都把**契约**埋在执行层里面。

Kiln 把契约单独拎出来做一层，原因只有一个：**同一个契约要同时喂给三类消费者，而它们互不兼容。**

- 构建要它（产出可交付的清单）
- 宿主运行时要它（决定能不能调、调什么）
- agent 要它（决定值不值得调、怎么调）

如果契约长在执行层里，每加一个 agent 生态就要动执行层。拎出来之后，加一个生态只需加一个适配器。

## 一条调用怎么走

```
agent 发起 invoke
   │
   ├─ surface   解析参数、决定策略档位
   ├─ pact      确认该工具已声明（未声明直接拒绝，不进入执行）
   ├─ host      resolveGrants(清单申请 × 宿主上限) → 逐能力得出 allow/deny + 理由
   │            ↓
   ├─ host      构造 CastContext，注入受限句柄（shell / file / store / net）
   │            ↓
   ├─ cast      业务代码跑，只能通过句柄触碰外部世界
   │            ↑ 每次越权都被网关记账
   ├─ host      动词返回后结算：账上有拒绝 → 覆盖返回值并抛出
   └─ surface  按 --json 输出单条结果，退出码 0/1/2
```

## 三个刻意的设计决定

### 1. 拒绝不可被吞

cast 的代码可以把异常 catch 掉，当成「业务失败」返回。这在业务错误上是合理的（文件不存在、参数不合法），但在授权拒绝上是**灾难**——一次越权就变成了一个看起来正常的业务结果。

解法：网关在拒绝时除了抛异常，**另记一笔账**。执行器在动词返回后检查这本账，有记录就直接覆盖返回值。cast 改不了这本账。

为此专门写了一个测试（`test/runner.spec.ts` 的「越界读文件被拒，且 cast 无法把拒绝吞成业务结果」）。第一版实现没做记账，测试直接失败——这是个真实的设计缺陷，不是测试写错了。

### 2. 校验一次报全部

`validateManifest()` 不抛异常、不在第一个错误处中止，而是**收集所有问题一次返回**。

理由是给 agent 用的：修一个、跑一次、再修一个，是 token 与轮次的双重浪费。一次给全，一轮改完。

代价是校验函数比「遇到错就 throw」长得多。值得。

### 3. 构建不打包

`forge` 只产出契约产物（规范化清单、MCP 工具表、紧凑说明、各适配器视图），**不产出可执行包**。

这是刻意的克制。打包会把项目绑死在某一个运行时上——上游一个绑 Vite/Node，一个绑 Tauri iframe，各有各的历史包袱。Kiln 现在只负责「把契约说清楚」，运行形态留给宿主和适配器决定。等真需要打包时再加，那时候才知道该为谁打。

## 数据在哪

| 路径                   | 内容                               | 谁写       |
| ---------------------- | ---------------------------------- | ---------- |
| `cast.json`            | 清单，唯一可信来源                 | 人 / agent |
| `src/pact.ts`          | 实现                               | 人 / agent |
| `.kiln/data/<castId>/` | `{castdata}` 落点，含 `store.json` | 宿主       |
| `.kiln/out/`           | `forge` 产物                       | 构建       |

`{castdata}` 每个 cast 一个目录，天然隔离。`store.json` 是每应用 KV，不跨 cast 共享。

## 已知未完成

诚实列出来，避免被当成已交付能力。

**安全边界止步于逻辑层。** 默认执行仍在宿主进程内，能力网关管得住「走 `ctx.cap` 的路径」，管不住 cast 主动 `import("node:fs")`。融合层提供了 Worker 级沙箱（内存上限、超时终止、崩溃隔离）与子进程隔离，但都不是 OS 或容器边界——跑完全不可信的代码之前，这块必须补上。

**交付的仍然是源码，不是可执行产物。** `forge` 只出契约；`artifact` 打包的是源码 + 哈希 + 签名，让宿主能校验、能回滚，但它不包含运行时。

**多租户与远程接入在融合层，不在内核。** HTTP/SSE MCP 端点（`kiln mcp-http`）和租户数据隔离（`--tenant`）都已可用，但 SDK 还没提供，内核单次执行仍然是一个 cast、一个策略档位。

**计量与更聪明的检索还欠着。** 配额有示例插件，计费没有；发现层已经是字符 n-gram 向量 + `intents` 关键词的混合检索，神经 embedding 与跨语言查询仍未提供。
