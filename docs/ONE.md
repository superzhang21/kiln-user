# Kiln One · 面向普通用户的日常工具箱

给 AI 助手配一个本地的「日常事务收纳与执行盒」：把散落在聊天、截图、文件、链接里的信息与待办收成一份可查、可汇总、可推进的台账。用户只说一句话，agent 负责收纳、查找、汇总与推进。

`one/` 这个文件夹交给 agent（或双击启动）就能用。用户不需要知道 cast、MCP、契约、策略档位这些词。适用范围是本机、单用户、可信内置应用。

## 1. 为什么需要它

AI 聊完就忘，结果停在对话里；资料散落在聊天、截图、链接之间，找一次要翻半天；想把 AI 工具接进日常，还得装依赖、写 JSON、配权限——大多数人在第一步就放弃。

Kiln One 换了个思路：不要求用户先理解工具，只要求把一个文件夹交出去。收纳的结果落在本地，越用越厚；检索只回少量命中与片段，不把整库塞进上下文；接入是一条命令的事，注册和自检都自动完成；数据不出本机，默认 `strict`，不联网、不执行命令，随时可以撤销。

## 2. 谁用，怎么用

主力是每天用 AI 助手但不写代码的人：学生、上班族、自由职业者、家长、内容创作者。他们不缺工具，缺的是「别让我配置」。会装 AI 客户端但不愿维护脚本的人也能上手；需要 SDK 或企业多租户的开发者不在这个范围内。

典型的一天大概是这样：

- **随手存**：把截图文字、链接或一句话发给 agent「存一下」，自动去重、分类、落到本地。
- **随时找**：「帮我找上个月的房租发票」，只回一条命中与出处。
- **每天问**：「今天要做什么」，`observe` 返回 2 KB 内的今日摘要。
- **每周汇总**：「这周汇总一下并导出」，`digest` 给紧凑摘要，`export_list` 写本地文件。
- **换 agent 不丢上下文**：同一份本地数据能被多个客户端连上，不用重新交代背景。

## 3. 交付物

```
one/                          可整体交给 agent 或复制走的一键包
  AGENT.md                   给 agent 读的机器可读接入说明（勿删）
  up.json                    默认策略、自检参数、人类可读权限清单
  kiln-up.mjs / .cmd / .sh   agent 命令入口 / Windows 双击 / POSIX 入口
  checksums.json             由 `kiln seal` 生成的 sha256 完整性清单
  README.md                  面向普通用户的三步说明
  apps/catchall/             开箱自带的默认应用「随手收」
  .mcp.json                  运行时生成的可导入 MCP 配置
  .kiln/state/               运行时生成的连接/权限状态
  .kiln/data/                应用数据（只在本机）

packages/one/               产品层实现（零运行时依赖）
  src/bundle.ts              配置校验、seal / verify 完整性
  src/permissions.ts         授权状态（pending / granted / revoked）
  src/clients.ts             客户端探测、幂等注册、备份、撤销
  src/handshake.ts           真实 MCP stdio 握手自检
  src/autostart.ts           可选开机自启（跨平台、可逆）
  src/up.ts                  up / down / status / seal / permissions 编排
  src/panel.ts               本机状态面板 HTTP 服务
  web/panel.html             零依赖面板界面
```

## 4. 架构

依赖单向向下，产品层只复用内核，不改四动词语义。

| 层     | 位置                       | 职责                                       |
| ------ | -------------------------- | ------------------------------------------ |
| 交付层 | `one/`                     | 自描述包、`AGENT.md`、完整性清单           |
| 产品层 | `packages/one`             | 启动编排、授权、客户端注册、自检、状态面板 |
| 契约层 | `grain` / `forge` / `pact` | 单一清单、四动词、强制示例、适配器         |
| 运行层 | `host` / `surface`         | 能力网关、拒绝记账、CLI、MCP stdio、Studio |

一次 `kiln up` 的数据流：

```
用户把包交给 agent / 双击
  → AGENT.md 被读取，执行 node one/kiln-up.mjs
  → 完整性校验（缺失 / 篡改 / 未登记文件，一次报全部）
  → 契约校验（loadCast，多个 cast 并行加载）
  → 授权：首次交付视为一次授权；revoked 必须由用户显式恢复
  → 探测并合并写入已安装客户端的 MCP stdio 配置（幂等 + .bak 备份）
  → 拉起真实 MCP 服务：initialize → tools/list → describe → 只读演练
  → 输出结构化就绪报告；自检失败自动回滚已注册的连接
```

stdio 服务由 agent 客户端按需拉起，配置持久化即「常驻」，不需要额外守护进程。可选开机自启只负责开机后重新确认连接。

一次日常调用：

```
用户一句话 → agent 选工具 → MCP tools/call
  → surface 解析 → pact 确认声明 → host 求交授权并注入 ctx.cap
  → cast 本地完成工作 → 只回小摘要 → 状态与数据落在 .kiln/data
```

## 5. 几个关键决定

**通用性放底座，简单性放默认。** 平台能装任意 cast，但新用户只看到一个应用、一个入口、零术语。

**交付即授权，但撤销是真的。** 用户主动把包交给 agent 视为一次授权，权限清单同时展示；一旦 `revoked`，下一次 `up` 不会悄悄把它恢复，必须显式 `grant`。

**完整性先于执行。** `apps/` 下任何未登记或被改动的文件都会拦下启动，默认只跑已 seal 的可信应用。索引只是缓存，记录本身才是事实来源——索引坏了就从记录重建，不丢用户数据。

其余几条融在细节里：默认 `strict`，默认应用只申请 `store` 与 `{castdata}` 下的 `file`，不申请 `net` / `shell`；`observe` 有 2 KB 预算并用 `truncated` 明示，检索最多回 10 条，`act` 一轮就带回新状态；所有失败都是 `code` / `message` / `hint` / `docs`，一次报全部，agent 可以照着 `hint` 自愈；写用户配置前留 `.kiln-one.bak`，`down` 只删自己加的键。

## 6. 明确不做

这一层不做笔记软件、不做云账号、不做 agent 运行时，也不把首屏做成插件市场，更不向普通用户暴露契约与策略这些概念。

同样不把 MCP 声明当安全沙箱，不宣称能安全运行未审阅的第三方代码。HTTP/SSE 端点、发现层与多租户隔离由融合层提供；应用市场服务端、计量结算与神经 embedding 检索不在这一层。

## 7. 验收指标

| 指标           | 目标                               | 当前验证方式                                        |
| -------------- | ---------------------------------- | --------------------------------------------------- |
| 零人工配置率   | 100%                               | 一键包 `up` 端到端测试，无需手写任何配置            |
| 首次连接成功率 | 100%                               | 握手自检 `handshake.ok === true`                    |
| 自检轮次       | 1 轮                               | `initialize` → `tools/list` → `describe` → 只读演练 |
| 上下文体积     | `observe ≤ 2048 B`，`find ≤ 10` 条 | 单元测试断言字节与条数                              |
| 可撤销         | 授权与连接都可一键撤销             | 面板与 CLI 回归测试                                 |
| 失败可自愈     | 每条错误带可执行的 `hint`          | 完整性、授权、握手失败用例                          |
