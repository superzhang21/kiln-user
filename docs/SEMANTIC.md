# 语义化发现

> 目标：用户不必记住关键词，直接问「哪个工具能帮我把大日志压成摘要」也能找到应用。

## 1. 为什么需要

关键词倒排要求用户说出与清单完全一致的词。真实用户会说「房贷计算」「上周的账单」「把这段记一下」，这些说法与 `intents` 往往只部分重合。语义索引把清单文本映射成向量，用相似度找回最接近的应用。

## 2. 实现（零依赖）

```text
清单文本 = 标题 + 摘要 + intents + 工具名/用途 + 动作名/用途
        ↓ 字符 1–3 gram + 英文词
FNV-1a 哈希到 256 维
        ↓ 词频加权 + L2 归一化
向量（number[256]）
```

查询侧同样编码，排序分数为：

```text
score = 0.7 × 余弦相似度 + 0.3 × 关键词命中率
```

- 中文按字符 n-gram，能覆盖「日志/摘要」「提交/作者」这类片段重合，不需要分词词典。
- 英文词单独加权，兼顾 `git`、`mcp` 这类专名。
- 过滤 `score ≤ 0.02` 的结果，避免给 agent 塞无关应用。

## 3. 用法

```bash
kiln discover "把很大的日志压成一份小摘要" --dir examples --json
kiln discover "看最近的代码提交和作者分布" --dir examples --limit 3 --json
```

输出：

```json
{
  "ok": true,
  "command": "discover",
  "mode": "semantic",
  "hits": [{ "id": "ledger", "score": 0.62, "lexical": 0.5, "dir": "..." }]
}
```

`lexical` 是关键词命中率，便于排查「为什么它排第一」。宿主可把 `hits` 前几条的 `id` 与 `summary` 交给 agent 选择，而不是把全部清单塞进上下文。

## 4. 局限

1. **不是神经 embedding**：同义词（「笔记本」vs「记事」）与跨语言（中文查询命中英文描述）能力有限。
2. **维度固定 256**：应用数量到数百级仍可用，再大需要换 HNSW 或外部向量库。
3. **索引在内存重建**：每次 `discover` 重新扫描目录；几十个应用是毫秒级，规模更大时应缓存到 `.kiln/index/`。
4. **建议把 `intents` 写全**：用户可能说的动词、名词、场景都写进去，比只写两三个标签效果更好。

## 5. 验证

`test/semantic.spec.ts` 覆盖：自然语言查询命中正确应用、向量 L2 归一化、空查询返回空结果。
